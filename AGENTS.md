## Карта проекта и источники

- `loader/` — proxy `version.dll`, загрузка модов и диагностика исключений;
  `mods/<name>/` — отдельные DLL, дефис в имени каталога становится подчёркиванием в DLL.
- `shared/` — общие API, лог, INI, ввод, D3D9/ImGui, F10 hub и игровые ресурсы;
  `scripts/risenmods/` — `bin/scripts/Script_RisenMods.dll`; `installer/` — установщик.
- `rust/risen-formats/` — форматы архивов/мира/шаблонов, VFS, геометрия и коллизии;
  `rust/risen-cli/` — CLI `risen`. Логику форматов и геометрии держи в библиотеке, CLI — команды и вывод.
- `notes/reference-implementations.md` — **начинай отсюда**: каталог «как сделано X» (хуки, кнопки и страницы
  в меню игры, скрипты, INI/лог, правки мира) со ссылками на эталонный код. Повторяй найденный там приём, а не
  исследуй заново; новый подтверждённый приём — добавь строкой туда же.
- `notes/world-editing.md` — слои, секторы, установка/откат;
  `notes/vfs-rev2045.md` — реальные приоритеты VFS;
  `notes/geometry-placement.md` — ground/snap/contact и ограничения физики;
  `notes/asset-editing.md` — пробные собственные модели, cooking/cache и ещё не проверенные в игре возможности;
  `notes/world-debug.md` — управление объектами/камерой;
  `notes/crash-diagnostics.md` — текущая диагностика загрузки/выгрузки мира.
- Старый редактор и его исходники находятся вне проекта: `D:\RisenModding\ed_new\Risen Editor`
  и `D:\RisenModding\ed_src\RisenEditor-master`. Его сериализация содержит известные ошибки:
  проверяй по native RE/корпусу, не копируй предположения без проверки. Свой GUI пока в плане.

## Rust: сборка и проверки

- Toolchain — GNU x64 на D:, отдельно от MSVC для C++. Если текущая оболочка не унаследовала окружение:
  `$env:RUSTUP_HOME='D:\Rust\rustup'`, `$env:CARGO_HOME='D:\Rust\cargo'`;
  запускай `D:\Rust\cargo\bin\cargo.exe` из `rust/`.
- Команды: `cargo build --workspace`, `cargo test --workspace`, `cargo build --release`.
  CLI для PowerShell из корня репозитория: `.\rust\target\release\risen.exe --help`;
  игровой корень определяется по родительским каталогам или через `--game <folder>`.
- `rust/.cargo/config.toml` задаёт `D:/Rust/tools/llvm-dlltool.exe`: GNU dlltool требует отсутствующий as.exe.
  При проблемах после обновления toolchain смотри объяснение в этом файле и TODO 5.21.
- Для изменений форматов требуются byte-identical round trips на соответствующем игровом корпусе
  (`lrent-check`, `tple-check`, `projects-check`, `world-data-check` и др.) и проверки сохранности неизвестных данных.
- Для геометрии используй релевантный `tools/test-*.ps1`: contact, ground-contact, height-correction,
  curved-ground, transforms, xcom и др. Скрипты обычно используют release CLI — сначала пересобери его.
  Смотри параметры/код скрипта перед запуском: некоторые устанавливают сцены, другие только пишут в build/tests.
  `test-xcom.ps1 -PhysXDirectory <path>` дополнительно сверяет декодирование с native PhysX 2.x (x86 helper).
- C++ проверки: `tools/check-world-debug.py` сверяет экспорты с игровыми DLL;
  `tools/check-world-debug-controls.bat` проверяет команды/камеру;
  `tools/check-world-trace.bat` — диагностические wrappers и дампы. Последний использует собранную shared.lib.
  Выбирай проверки по изменённому компоненту. Для правок только документации сборка не нужна.

## Правки мира и установка

- Игра читает смонтированную VFS, а не просто все PAK на диске. Используй `risen-formats::vfs` и `risen vfs`;
  короткое неоднозначное имя должно давать отказ. Не подменяй правила VFS догадками по timestamp.
- Изменения мира — loose overrides под `../data/`, исходные PAK сохраняй. Для загрузки loose-файлов
  нужен `[Root] NoPhysical=false` в `../bin/mountlist_packed.ini`; CLI сам настройку не меняет.
  Перед её изменением сохрани текущий файл, как и текущие loose overrides: backup/bin-original их не покрывает.
- Сначала подготовь `--dry-run` и результат в `build/tests/` через `--out`/`--out-dir`, где команда поддерживает.
  Отсутствие `--out` у изменяющей команды может означать запись прямо в игру.
- Устанавливай/откатывай файлы только при закрытом `../bin/Risen.exe`; проверяй полный путь процесса,
  чтобы не принять наш CLI `risen.exe` за игру. Перед записью — проверенная копия текущего состояния,
  включая отсутствие новых файлов; после — parse/readback и SHA256 посторонних файлов.
- `layer-create` и установщики сцен используют `backup/world-edits/<id>` с manifest и снимками;
  откат: `.\rust\target\release\risen.exe world-restore 'backup\world-edits\<id>'`.
  Более поздние изменения по умолчанию блокируют откат: выясни зависимость копий, не добавляй `--force` автоматически.
  Не предполагай, что все команды CLI уже имеют такой же транзакционный backup.
- Для моделей/коллизий и их каталогов есть отдельные `asset-install <bundle.json> [--dry-run]` и
  `asset-restore <backup>`: копии в `backup/asset-edits/`, проверка staged baseline и последующих правок.
  World/asset manifest scopes различаются; не откатывай asset-копию через world-restore.
  Оба каталога (`compiled_meshes.bin` и `compiled_collision_meshes.bin`) должны соответствовать ресурсам.
  `tools/install-mesh-assets.ps1 -Stage <build/tests/...> [-Install]` сначала проверяет установку/откат
  в изолированном дереве; формат bundle и текущее ручное тестирование описаны в notes/asset-editing.md.
- Для точечного deploy есть `tools/deploy-world-debug.ps1` и `tools/deploy-world-trace.ps1`:
  проверяют закрытую игру, создают manifest, сохраняют пользовательские INI и сверяют посторонние файлы.
  Перед запуском учитывай их эффект: первый включает World Debug при первой установке,
  второй включает WorldTrace/DumpFirstChance и сохраняет текущую тестовую сцену.
- Пользователь 2026-10-16 разрешил агенту самому закрывать игру после завершённого пользователем теста
  перед заменой файлов. Не проси его закрывать каждый раз; используй точный путь bin/Risen.exe,
  предпочитай CloseMainWindow и проверяй завершение процесса перед записью.
- Позиции/зазоры CLI — сантиметры, Y вверх; mesh и физический collider могут различаться.
  Соблюдай ограничения native scale/adaptation из notes/geometry-placement.md. ground с выборкой,
  contact и ограниченный вертикальный sweep не доказывают полную эквивалентность runtime PhysX.
- Объекты между кадрами/командами находи заново по GUID. Храни только скопированные данные,
  не указатели на entities/PS/effects. Проверяй исходные байты, PE identity и vtable/IAT sites перед hooks.
- Автоматическая проверка и подготовка сцены не означают ручного успеха. Отдельно записывай подтверждённые
  пользователем визуальные проверки, движение/коллизии, новую игру и save/load; не обобщай сверх его отчёта.
  Диагностический лог или успешный повторный запуск не означают устранения причины вылета.
